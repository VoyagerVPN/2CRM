# 2CRM

CRM для строительных объектов и задач. Постановщик создаёт и распределяет работу, исполнитель видит свои задачи и отправляет результат на проверку.

Реализованы пять экранов: вход, объекты, карточка объекта, карточка задачи с историей, мои задачи. Есть две роли, серверные переходы статусов, переназначение без смены статуса и удаление с сохранением истории. Карточка задачи использует выбранный вариант C: заметный статус и исполнитель, общий ход работы, автор, дата и история. Общая навигация расположена слева.

## Локальный запуск

Нужен Node.js 24.22 или новее. Версии пакетов зафиксированы в lockfile.

1. Установите зависимости: `npm ci --ignore-scripts`.
2. Скопируйте `.env.example` в `.env.local`, заполните URL Supabase и publishable key своего проекта.
3. Примените SQL-файлы из `supabase/migrations/` к пустому проекту Supabase в порядке имён. Например, выполните их по очереди в SQL Editor. Нужны Auth по email/паролю и Data API для схемы public. Частная схема private в Data API не открывается.
4. В Supabase Authentication отключите Allow new users to sign up.
5. Создайте пользователей и их строки profiles через штатный Admin API или локальный скрипт ниже.
6. Запустите `npm run dev`. Адрес: http://127.0.0.1:5173.

В браузер передаются только VITE_SUPABASE_URL и VITE_SUPABASE_PUBLISHABLE_KEY. Секретный ключ браузерному приложению не нужен.

## Демонстрационные пользователи и данные

Для отдельного тестового проекта можно использовать локальные серверные скрипты:

1. Создайте файл `.cache/private/admin.env` с переменной `SUPABASE_SECRET_KEY`, содержащей secret key своего проекта. Файл исключён из Git. Не называйте эту переменную VITE_*.
2. Выполните `npm run provision`: скрипт создаст двух постановщиков и двух исполнителей с автоматически подтверждённым email через Supabase Admin API. Случайные пароли запишутся в `.cache/private/test-accounts.json`, без вывода в терминал.
3. Выполните `npm run seed:demo`: появятся три демонстрационных объекта и шесть задач во всех пяти статусах. Начальные переходы выполняются через обычные пользовательские API, история сохраняется.

Системные таблицы Auth вручную не изменяются. Для выдачи реальных аккаунтов нужен отдельный административный процесс; интерфейс регистрации и управления пользователями в ТЗ не входит. Доступы передавайте отдельно от публичного репозитория.

## Проверки

```powershell
npm run typecheck
npm run build
npm test
npm run test:integration
```

Интеграционные тесты требуют подготовленных локальных аккаунтов и серверного ключа. Они проверяют настоящий REST/RPC API от двух постановщиков, двух исполнителей и анонимного клиента. Для подготовки и удаления собственных временных фикстур используется Admin API; бизнес-действия проверяются от обычных пользователей. Запускайте тесты в отдельном тестовом проекте, не на рабочих данных. Node test runner закреплён с --test-isolation=none.

Команда `npm run check:supabase` проверяет достижимость REST API и открытые настройки Auth; она не заменяет интеграционные проверки.

На Windows автоматические команды запускаются скрыто через `node scripts/run.mjs node <файл> <аргументы>`. Запускатель передаёт локальные временные каталоги дочернему процессу и не использует оболочку. Обычные npm-команды выше предназначены для ручного запуска.

## Стек и размещение

React + TypeScript, Vite, Ant Design, React Router, Supabase Auth/PostgreSQL. Отдельный прикладной сервер и ORM не требуются. Правила записи выполняются внутри транзакционных функций базы, чтение защищено RLS.

Сборка находится в dist. vercel.json задаёт Vite, установку npm ci --ignore-scripts и возврат index.html для клиентских маршрутов. В Vercel передаются только две публичные переменные VITE_SUPABASE_URL и VITE_SUPABASE_PUBLISHABLE_KEY; серверный ключ там не требуется. Внешнее демо готовится к размещению.

## Известные ограничения

При конфликте параллельного редактирования форму требуется переоткрыть. Через прямой API комментарий возврата пока может состоять из tab/newline/NBSP, хотя UI это запрещает. Оба случая подтверждены ревью и ещё не исправлены; подробности в docs/VERIFICATION.md.
