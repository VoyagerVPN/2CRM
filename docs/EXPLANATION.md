# Как работает CRM

Руководитель создаёт объект, например строящийся дом, затем добавляет задачи и назначает исполнителей. В карточке видно, что нужно сделать, на каком объекте, кому поручено и в каком состоянии находится работа.

Исполнитель входит в свою учётную запись и видит назначенные ему задачи. Новую задачу он берёт в работу, после выполнения отправляет на проверку. Постановщик принимает результат либо возвращает его с обязательным пояснением, что исправить. После исправлений исполнитель может отправить работу повторно. Каждая смена состояния сохраняет участника, время и комментарий.

Права проверяет сама база данных. Ограничение действует и при обращении к серверу в обход кнопок интерфейса: исполнитель не получает чужие задачи и не может назначить себе права руководителя. В интерфейсе также скрыты недоступные действия. Историю через пользовательский API нельзя подделать, переписать или удалить.

Постановщик может сменить исполнителя без потери текущего состояния. Даже принятая задача останется принятой. Прежний исполнитель теряет доступ, а новый видит переданную задачу и её историю.

Удаление убирает объект или задачу из рабочих списков, сохраняя историю в базе. При удалении объекта скрываются и его задачи; перед этим приложение показывает предупреждение и число затрагиваемых задач. При одновременном изменении одной записи второй пользователь получает сообщение о конфликте, чтобы не перезаписать чужой результат.

В этой версии нет сроков, приоритетов, файлов, уведомлений вне открытого приложения и самостоятельной регистрации. Учётные записи выдаются отдельно. Для проверки подготовлены демонстрационные объекты и две роли пользователей; это вымышленные данные.
