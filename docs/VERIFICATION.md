# Проверка реализации

Срез на 7 ноября 2026 года. В рабочем приложении реализован выбранный вариант C «Фокус исполнителя» с левым меню, цветными статусами, общим ходом работы и историей.

## Автоматические проверки

Свежий прогон: TypeScript без ошибок, production-сборка Vite, 7 модульных и 13 интеграционных тестов (11 основных и 2 отдельных сценария сброса). Все завершились успешно. Интеграционные тесты обращаются к настоящему Supabase от двух постановщиков и двух исполнителей.

1. Чтение своей задачи и запрет чужой, включая вложенный список общего объекта.
2. Создание и редактирование объекта двумя постановщиками; запрет исполнителю и устаревшей версии.
3. Создание задачи с автором и начальной историей; редактирование и переназначение без фиктивного перехода.
4. Полный цикл из семи событий, проверка ролей, возврат с комментарием, переназначение в работе и после принятия, запрет вставки/правки/удаления истории.
5. Удаление задачи с сохранением истории.
6. Атомарное удаление объекта с задачами, проверка числа задач и сохранение истории.
7. Два одновременных перехода: один успех, один конфликт и одна новая запись истории.
8. Запрет анонимного доступа, открытой регистрации, изменения профиля и повышения роли через user_metadata.
9. Изменение доступа к объекту и истории после переназначения и удаления последней своей задачи.
10. Отклонение всех пробельных комментариев без изменения задачи/истории; положительный многострочный комментарий.
11. CHECK истории отвергает null и пробельный комментарий даже при подготовке доверенной административной фикстуры.

Модульные тесты проверяют HTTP-таймаут/внешнюю отмену, шкалу всех пяти статусов, сохранение черновика при конфликте, явное повторное сохранение с актуальной версией и повторный конфликт при ещё одной конкурентной правке.

## Браузер

На локальном сервере в браузере Кодекса проверены все пять экранов, вход/выход и восстановление прямой ссылки. Постановщик видит обе задачи общего объекта; исполнитель только свою. Прямая ссылка на чужую задачу не раскрывает данные. У исполнителя нет административных действий; у постановщика в состоянии проверки есть принятие и возврат.

Ранее на реальной карточке C пройден полный цикл с доработкой и принятием. История содержит все семь событий. Переназначение принятой задачи сохраняет статус и не добавляет переход. На узком экране ширина документа совпадает с доступной шириной 341 CSS px; боковая навигация уходит в меню, карточка не обрезается.

Подтверждение удаления и отмена проверены в интерфейсе, фактическое удаление с сохранением истории проверено через API.

## Демоданные

В рабочих списках осталось три демонстрационных объекта и шесть задач во всех пяти статусах. Проверочный объект скрыт штатной функцией удаления; все семь событий истории его задачи сохранены. Есть два постановщика и два исполнителя. Серверный ключ хранится отдельно от репозитория. Четыре общих демо-пароля опубликованы по прямому разрешению пользователя для кнопок быстрого входа.

## Исправления после ревью

- Конфликт редактирования больше не оставляет форму со старой версией. Введённые поля сохраняются, компактный блок показывает различия с сервером. «Загрузить актуальные данные» заменяет поля и версию формы; «Сохранить мой вариант» отправляет черновик с показанной версией. Новая параллельная правка снова вызывает конфликт, без слепой перезаписи.
- База отклоняет комментарии только из пробельных символов, включая tab/newline/NBSP и остальные Unicode-пробелы браузера. Одна проверка private.has_non_whitespace применяется в RPC и CHECK истории; null тоже отклоняется для возврата на доработку. Старые записи истории не изменялись.
- Добавлены два модульных сценария версии/черновика и два интеграционных сценария комментария/ограничения истории. Регрессии сначала воспроизводили ошибки, затем прошли после исправлений.
- В браузере Кодекса проверены повторный конфликт после показа сравнения, явное сохранение собственного варианта задачи и загрузка актуальных данных объекта с последующим обычным сохранением. Проверка проводилась на отдельной временной записи.

## Размещение и границы проверки

Production: [https://2crm.vercel.app](https://2crm.vercel.app), проект 2crm в Vercel, команда Voyager's projects. Проверены вход постановщика и исполнителя, список объектов, карточка объекта, собственные задачи и история, отказ в чужой задаче, обновление прямой ссылки на карточку и успешное сохранение формы. Сохранение идентичных полей увеличило версию задачи с 3 до 4, сохранив содержимое, статус in_review и три события истории. Во время этого прохода браузерных ошибок JavaScript не зафиксировано.

Сборка берётся из публичного GitHub VoyagerVPN/2CRM. В Vercel переданы только два публичных параметра Supabase. Серверный ключ сборке не нужен и не передавался. vercel.json задаёт SPA rewrite, установку без lifecycle-скриптов и dist; ветка Node.js закреплена на 24.x. Список env через коннектор прочитать не удалось (403); работоспособность параметров подтверждена реальным входом и Data API, а не предположением об этой ошибке.

При первом открытии из локальной сети был ERR_CONNECTION_RESET. После узкой сетевой правки в проекте Nokia новый сеанс браузера загрузил приложение. Причина исходного сетевого сбоя этим проектом не установлена.

- Размер основного JS-чанка около 1.42 MB, gzip 438 KB; Vite предупреждает о размере, сборка успешна.
- Security Advisor не сообщил замечаний к RLS/функциям; осталось предупреждение [Leaked Password Protection Disabled](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Открытая регистрация отключена.
- Проверены точные известные секретные значения в файлах-кандидатах, доступной истории Git и dist; на момент исправления конфликтов совпадений не было. Позднее пользователь разрешил публикацию четырёх демо-паролей для быстрого входа; они намеренно присутствуют в public-demo.ts и клиентской сборке. Серверный ключ остаётся запрещённым для Git и клиента. Это ограниченная проверка, не универсальный аудит всех возможных секретов.
- Все сочетания запрещённых переходов и ролей, пагинация более 20 строк, истечение сессии по времени и развёртывание в совершенно пустую вторую базу отдельно не проверены.

## Быстрый демо-вход

В браузере Кодекса локально проверены все четыре кнопки: соответствующие имя и роль в меню, у исполнителей собственные списки задач. Во время входа видны блокировка остальных действий и индикатор на выбранной кнопке. Три новых модульных сценария проверяют соответствие кнопок аккаунтам, отключённый/неполный режим и привязку публичной конфигурации к своему Supabase-проекту с явным отключением.

Добавление production-переменных через коннектор Vercel отклонено (403). По выбору пользователя используется публичная демо-конфигурация в Git; дополнительных env Vercel не требуется.

## Сброс демо

Новый API-тест сначала падал из-за отсутствия RPC, затем прошёл. Два сценария проверяют восстановление точных названий/описаний/исполнителей/статусов, 3 объекта/6 задач/15 исходных событий, повторный сброс обоими демо-постановщиками, сохранность прежней истории и запрет анониму, исполнителю и дополнительному постановщику вне списка. Сброс не запускают параллельно основным API-тестам.

В отдельной транзакционной проверке повреждён доверенный снимок: ошибка NOT NULL после начала архивирования полностью откатила объекты, задачи и историю; сравнение полного состояния совпало. Настройка снимка supabase/demo-reset-setup.sql выполнена и проверена на восстановленном демо. Развёртывание с нуля в другую базу по-прежнему не проверено.

Локально в браузере Кодекса проверены кнопка на входе, подтверждение, отмена и успешный сброс без входа в рабочий интерфейс. Использована актуальная настройка mask.closable из [документации Ant Design](https://ant.design/components/modal/). Security Advisor добавил информационное RLS Enabled No Policy для намеренно закрытой private.demo_reset_config; клиентских прав на таблицу нет. Прежнее предупреждение Leaked Password Protection Disabled сохраняется.
