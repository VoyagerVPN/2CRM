# Проверка реализации

Срез на 7 ноября 2026 года. В рабочем приложении реализован выбранный вариант C «Фокус исполнителя» с левым меню, цветными статусами, общим ходом работы и историей.

## Автоматические проверки

Свежий прогон: TypeScript без ошибок, production-сборка Vite, 2 модульных и 9 интеграционных тестов. Все завершились успешно. Интеграционные тесты обращаются к настоящему Supabase от двух постановщиков и двух исполнителей.

1. Чтение своей задачи и запрет чужой, включая вложенный список общего объекта.
2. Создание и редактирование объекта двумя постановщиками; запрет исполнителю и устаревшей версии.
3. Создание задачи с автором и начальной историей; редактирование и переназначение без фиктивного перехода.
4. Полный цикл из семи событий, проверка ролей, возврат с комментарием, переназначение в работе и после принятия, запрет вставки/правки/удаления истории.
5. Удаление задачи с сохранением истории.
6. Атомарное удаление объекта с задачами, проверка числа задач и сохранение истории.
7. Два одновременных перехода: один успех, один конфликт и одна новая запись истории.
8. Запрет анонимного доступа, открытой регистрации, изменения профиля и повышения роли через user_metadata.
9. Изменение доступа к объекту и истории после переназначения и удаления последней своей задачи.

Модульные тесты проверяют таймаут и внешнюю отмену настоящего HTTP-запроса, а также отображение всех пяти состояний в шкале прогресса.

## Браузер

На локальном сервере в браузере Кодекса проверены все пять экранов, вход/выход и восстановление прямой ссылки. Постановщик видит обе задачи общего объекта; исполнитель только свою. Прямая ссылка на чужую задачу не раскрывает данные. У исполнителя нет административных действий; у постановщика в состоянии проверки есть принятие и возврат.

Ранее на реальной карточке C пройден полный цикл с доработкой и принятием. История содержит все семь событий. Переназначение принятой задачи сохраняет статус и не добавляет переход. На узком экране ширина документа совпадает с доступной шириной 341 CSS px; боковая навигация уходит в меню, карточка не обрезается.

Подтверждение удаления и отмена проверены в интерфейсе, фактическое удаление с сохранением истории проверено через API.

## Демоданные

В рабочих списках осталось три демонстрационных объекта и шесть задач во всех пяти статусах. Проверочный объект скрыт штатной функцией удаления; все семь событий истории его задачи сохранены. Есть два постановщика и два исполнителя. Секретный ключ и пароли хранятся отдельно от репозитория.

## Известные дефекты

Зелёный штатный прогон не покрывает два случая, подтверждённых дополнительным ревью:

- После параллельного редактирования другим постановщиком открытая форма сохраняет старую версию записи. Повторное сохранение снова получает конфликт; требуется переоткрытие формы. Введённые поля при ошибке остаются. Для продолжения с черновиком нужно согласовать UX.
- Через прямой RPC обязательный комментарий возврата может содержать только табуляцию, перенос строки или неразрывный пробел. Пустая строка, null и обычные пробелы отклоняются, UI также отвергает пробельные поля, но серверная btrim-проверка недостаточна. Требуются исправление SQL и regression-тест.

Эти дефекты пока не исправлены. Защита от чтения чужих задач и подделки истории в проверенных API-сценариях работает.

## Размещение и границы проверки

Production: [https://2crm.vercel.app](https://2crm.vercel.app), проект 2crm в Vercel, команда Voyager's projects. Проверены вход постановщика и исполнителя, список объектов, карточка объекта, собственные задачи и история, отказ в чужой задаче, обновление прямой ссылки на карточку и успешное сохранение формы. Сохранение идентичных полей увеличило версию задачи с 3 до 4, сохранив содержимое, статус in_review и три события истории. Во время этого прохода браузерных ошибок JavaScript не зафиксировано.

Сборка берётся из публичного GitHub VoyagerVPN/2CRM. В Vercel переданы только два публичных параметра Supabase. Серверный ключ сборке не нужен и не передавался. vercel.json задаёт SPA rewrite, установку без lifecycle-скриптов и dist; ветка Node.js закреплена на 24.x. Список env через коннектор прочитать не удалось (403); работоспособность параметров подтверждена реальным входом и Data API, а не предположением об этой ошибке.

При первом открытии из локальной сети был ERR_CONNECTION_RESET. После узкой сетевой правки в проекте Nokia новый сеанс браузера загрузил приложение. Причина исходного сетевого сбоя этим проектом не установлена.

- Размер основного JS-чанка около 1.42 MB, gzip 437 KB; Vite предупреждает о размере, сборка успешна.
- Security Advisor не сообщил замечаний к RLS/функциям; осталось предупреждение [Leaked Password Protection Disabled](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Открытая регистрация отключена.
- Проверены точные известные секретные значения в файлах-кандидатах, доступной истории Git и dist; совпадений не найдено. Это ограниченная проверка, не универсальный аудит всех возможных секретов.
- Все сочетания запрещённых переходов и ролей, пагинация более 20 строк, истечение сессии по времени и развёртывание в совершенно пустую вторую базу отдельно не проверены.
